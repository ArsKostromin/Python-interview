<h1>Расскажи про MVT</h1>
Архитектура MVT (Model-View-Template) используется в Django, как реализация подхода, похожего на MVC (Model-View-Controller). Django адаптирует эту архитектуру под свои особенности, упрощая создание веб-приложений. Давайте разберем, что означает каждая часть MVT:

<h1> 1. Model (Модель) </h1>

Модель отвечает за работу с данными:

определение структуры данных,
взаимодействие с базой данных,
выполнение запросов.
В Django модели определяются как классы Python и используются для работы с базой данных через ORM (Object-Relational Mapping).

Пример:
python

from django.db import models

    class Book(models.Model):
        title = models.CharField(max_length=255)
        author = models.CharField(max_length=255)
        published_date = models.DateField()
        genre = models.ForeignKey('Genre', on_delete=models.CASCADE)

        def __str__(self):
            return self.title
        
Задачи модели:

Описание таблиц и их полей.
Работа с запросами:
Book.objects.all(), Book.objects.filter(title='Django').

<h1>2. View (Представление)</h1>

Представление обрабатывает бизнес-логику и решает, какой ответ отправить пользователю:

принимает HTTP-запросы,
взаимодействует с моделью,
подготавливает данные для передачи в шаблон (или возвращает ответ в другом формате, например, JSON).
Пример:
python
Копировать код
from django.shortcuts import render, get_object_or_404
from .models import Book

    def book_list(request):
        books = Book.objects.all()
        return render(request, 'books/book_list.html', {'books': books})
    
    def book_detail(request, pk):
        book = get_object_or_404(Book, pk=pk)
        return render(request, 'books/book_detail.html', {'book': book})
    
Задачи представления:

Взаимодействие с моделями для получения данных.
Определение логики ответа.
Передача данных в шаблоны для рендеринга.
<h1>3. Template (Шаблон)</h1>

Шаблоны в Django используются для формирования HTML-страниц на основе переданных данных. Это слой представления, отвечающий за отображение информации пользователю.

Шаблоны поддерживают:

цикл (for),
условные конструкции (if),
фильтры ({{ title|lower }}) и теги ({% block content %}).
Пример:

html
<!DOCTYPE html>
    <html lang="en">
    <head>
        <meta charset="UTF-8">
        <title>Books</title>
    </head>
    <body>
        <h1>Books</h1>
        <ul>
            {% for book in books %}
                <li>{{ book.title }} by {{ book.author }}</li>
            {% endfor %}
        </ul>
    </body>
    </html>

Задачи шаблона:

Формирование HTML-ответа на основе данных, переданных из представления.
Минимизация бизнес-логики (все сложные вычисления должны быть в моделях или представлениях).
Как работает MVT в Django?
Запрос: Пользователь отправляет HTTP-запрос на сервер Django.
Представление (View):
Получает запрос.
Использует модель для работы с данными (запросы к базе данных).
Подготавливает контекст (данные) для шаблона.
Шаблон (Template):
Получает данные из представления.
Генерирует HTML-ответ.
Ответ: Django возвращает сгенерированную HTML-страницу пользователю.
Отличие MVT от MVC
В архитектуре MVC (Model-View-Controller):

Controller обрабатывает запросы, взаимодействует с моделью и передает данные представлению.
View отвечает только за отображение (например, HTML).
В Django MVT:

Django берет на себя роль контроллера (обработка запросов/ответов, маршрутизация).
Разработчику остается настроить View (как бизнес-логику) и Template (как отображение).
Преимущества MVT
Разделение обязанностей:

Легко менять шаблоны без изменения логики.
Упрощает тестирование и поддержку.
Гибкость:

Можно использовать только часть архитектуры (например, создавать API без шаблонов).
Автоматизация:

ORM Django значительно ускоряет работу с базой данных.
Встроенные шаблоны позволяют быстро генерировать HTML.
Расширяемость:

Вы можете подключать сторонние приложения и библиотеки, не нарушая структуру проекта.

<h1>Памятка про методы в Python: `staticmethod`, `classmethod` и обычные методы</h1>

### 

#### 1. **Обычные методы**
- Методы класса, которые принимают первым аргументом ссылку на экземпляр класса (`self`).
- Используются для работы с данными конкретного объекта.

```python
class MyClass:
    def instance_method(self):
        return f"Called instance_method on {self}"
```

**Пример использования:**

```python
obj = MyClass()
print(obj.instance_method())  # Output: Called instance_method on <MyClass object>
```

---

#### 2. **`@staticmethod`**
- Не привязан к экземпляру или классу.
- Не принимает аргумент `self` или `cls`.
- Используется для логики, не зависящей от объекта или класса, но логически связанной с классом.

```python
class MyClass:
    @staticmethod
    def static_method():
        return "Called static_method"
```

**Пример использования:**

```python
print(MyClass.static_method())  # Output: Called static_method
obj = MyClass()
print(obj.static_method())  # Output: Called static_method
```

**Когда использовать:**
- Для вспомогательных функций, которые логически связаны с классом, но не требуют доступа к атрибутам экземпляра или класса.

---

#### 3. **`@classmethod`**
- Привязан к классу, а не к объекту.
- Принимает первым аргументом ссылку на класс (`cls`).
- Используется, когда метод должен работать с классом или его атрибутами, а не с конкретным объектом.

```python
class MyClass:
    class_variable = "class-level"

    @classmethod
    def class_method(cls):
        return f"Called class_method on {cls}, class_variable: {cls.class_variable}"
```

**Пример использования:**

```python
print(MyClass.class_method())  # Output: Called class_method on <class 'MyClass'>, class_variable: class-level
obj = MyClass()
print(obj.class_method())  # Output: Called class_method on <class 'MyClass'>, class_variable: class-level
```

**Когда использовать:**
- Для работы с данными или поведением на уровне класса, например, изменение или получение значения атрибута класса.

---

#### 4. **Методы уровня экземпляра (обычные методы) vs уровня класса**
- **Обычные методы (`instance_method`)**:
  - Доступ к атрибутам и методам конкретного объекта.
  - Используется чаще всего.

- **`@staticmethod`**:
  - Не требует информации об экземпляре или классе.
  - Функционально похож на обычные функции, но группируется внутри класса для логической связи.

- **`@classmethod`**:
  - Манипулирует атрибутами и поведением класса, а не объекта.
  - Полезен для создания альтернативных конструкторов или работы с атрибутами уровня класса.

---

#### 5. **Когда использовать какой метод?**
| Тип метода     | Использование                                                                                  |
|----------------|-----------------------------------------------------------------------------------------------|
| Обычный метод  | Когда метод работает с данными объекта или вызывает другие методы объекта.                   |
| `@staticmethod`| Для вспомогательных функций, не требующих доступа к экземпляру или классу.                   |
| `@classmethod` | Для методов, которым нужен доступ к классу, а не к конкретному экземпляру.                   |

---

#### 6. **Сравнение всех типов в одном классе**

```python
class Example:
    class_variable = "class-level data"

    def instance_method(self):
        return f"Called instance_method on {self}"

    @staticmethod
    def static_method():
        return "Called static_method"

    @classmethod
    def class_method(cls):
        return f"Called class_method on {cls}, class_variable: {cls.class_variable}"
```

**Пример вызова:**

```python
# Вызов обычного метода
obj = Example()
print(obj.instance_method())  # Output: Called instance_method on <Example object>

# Вызов статического метода
print(Example.static_method())  # Output: Called static_method


# Вызов метода класса
print(Example.class_method())  # Output: Called class_method on <class 'Example'>, class_variable: class-level
```

<h1>Что такое кастомный менеджер модели и ModelManager?</h1>
В Django менеджер модели предоставляет интерфейс для взаимодействия с базой данных. По умолчанию у каждой модели есть менеджер objects, который позволяет выполнять стандартные запросы, такие как .all(), .filter(), .get(), и т.д. Однако иногда требуется изменить поведение стандартного менеджера или добавить собственные методы — для этого используются кастомные менеджеры.

ModelManager
ModelManager — это базовый класс для создания кастомных менеджеров. Чтобы создать кастомный менеджер, нужно унаследоваться от этого класса и определить дополнительные методы.

Пример:
python

    from django.db import models
    class PublishedManager(models.Manager):
        def get_queryset(self):
            # Возвращает только опубликованные объекты
            return super().get_queryset().filter(is_published=True)

<h1>SOLID</h1>
SOLID — это набор принципов проектирования программного обеспечения, предложенных Робертом Мартином (Robert C. Martin), также известным как "Дядя Боб". Эти принципы помогают создавать программное обеспечение, которое легко сопровождать, модифицировать и расширять. Каждый принцип представляет собой букву акронима SOLID:


1.<h2> S — Single Responsibility Principle (Принцип единственной ответственности)</h2>
Суть: У каждого класса должна быть только одна причина для изменения.
Это означает, что класс должен выполнять только одну задачу.


<h2>2. O — Open/Closed Principle (Принцип открытости/закрытости)</h2>
Суть: Программные сущности должны быть открыты для расширения, но закрыты для модификации.
Это означает, что при добавлении новых функций не следует изменять существующий код.


<h2> 3. L — Liskov Substitution Principle (Принцип подстановки Барбары Лисков) </h2>
Суть: Объекты дочернего класса должны быть взаимозаменяемы с объектами родительского класса.
Наследование не должно нарушать ожидаемое поведение базового класса.


<h2>4. I — Interface Segregation Principle (Принцип разделения интерфейсов)  </h2>
Суть: Клиенты не должны зависеть от интерфейсов, которые они не используют.
Это означает, что большие интерфейсы следует разбивать на более мелкие и специализированные.


<h2> D — Dependency Inversion Principle (Принцип инверсии зависимостей)  </h2>
Суть: Модули верхнего уровня не должны зависеть от модулей нижнего уровня. Оба должны зависеть от абстракций.
Абстракции не должны зависеть от деталей. Детали должны зависеть от абстракций.


<h1>Что такое авторизация и аутентификация и чем они отличаются?</h1>
Аутентификация и авторизация — это два разных, но взаимосвязанных процесса, связанных с безопасностью приложений и систем. Они часто используются вместе, но выполняют разные задачи.
<br>
<br>
Аутентификация (Authentication)
Определение: Процесс проверки личности пользователя.
Цель аутентификации — удостовериться, что пользователь действительно тот, за кого себя выдает.
<br>
<br>
Авторизация (Authorization)
Определение: Процесс предоставления пользователю доступа к определённым ресурсам или функциям на основании его прав.
Цель авторизации — определить, что пользователь может или не может делать в системе.

<h1>Что такое Access Token и Refresh Token и как из защитить?</h1>

Access Token (Аксес-токен)
Что это?
Краткоживущий токен, который используется для аутентификации и авторизации при доступе к защищённым ресурсам API.
<br>
<br>
Refresh Token (Рефреш-токен)
Что это?
Долгоживущий токен, который позволяет получить новый access-токен после его истечения.
<br>
<br>
Для защиты придумали механизм ратации, он заменяет Refresh Token каждый раз когда мы получаем новый Access Token.
<br>
<br>
Как работают вместе?
<br>
Пользователь аутентифицируется и получает access-токен и refresh-токен.
Клиент использует access-токен для запросов к API.
Когда access-токен истекает, клиент отправляет refresh-токен на сервер, чтобы получить новый access-токен.
Если refresh-токен истёк или недействителен, пользователь должен пройти повторную аутентификацию.

Объектно-ориентированное программирование (ООП) — это подход к разработке программ, в котором ключевыми концепциями являются объекты и их взаимодействие. Объекты представляют собой сущности, которые могут иметь свойства (атрибуты) и поведение (методы). ООП помогает создавать масштабируемые, удобные в поддержке и повторном использовании программные системы.

Основные принципы ООП:
1. Абстракция
Суть: Сокрытие сложных деталей реализации и предоставление пользователю только необходимых интерфейсов.
Зачем это нужно:
Упрощает взаимодействие с объектом.
Фокусируется на решении задачи, а не на реализации.
Пример: Автомобиль — вы управляете машиной через руль, педали и переключатели, не задумываясь, как работают двигатель или трансмиссия.
2. Инкапсуляция
Суть: Объединение данных (свойств) и методов (функций) в одном объекте, а также ограничение доступа к ним.
Зачем это нужно:
Защищает данные от неправильного использования.
Упрощает изменения и отладку, так как детали реализации скрыты.
Реализация:
Используются модификаторы доступа:
public — доступен всем.
private — доступен только внутри объекта.
protected — доступен объекту и его наследникам.
Пример:
python

        class BankAccount:
            def __init__(self, balance):
                self.__balance = balance  # Приватное свойство
            
            def deposit(self, amount):
                if amount > 0:
                    self.__balance += amount
            
            def get_balance(self):
                return self.__balance
4. Наследование
Суть: Создание нового класса на основе существующего.
Зачем это нужно:
Повторное использование кода.
Создание иерархии классов.
Реализация:
Наследник наследует свойства и методы родительского класса.
Может добавлять новые свойства/методы или переопределять существующие.
Пример:
python

        class Animal:
            def speak(self):
                return "I can make a sound"

        class Dog(Animal):
            def speak(self):
                return "Woof"
        
4. Полиморфизм
Суть: Возможность объектов разных классов использовать один и тот же интерфейс.
Зачем это нужно:
Универсальность кода.
Возможность менять поведение методов в подклассах.
Реализация:
Один метод может работать с разными типами объектов.
Пример:
python

        class Animal:
            def speak(self):
                pass
        
        class Cat(Animal):
            def speak(self):
                return "Meow"
        
        class Dog(Animal):
            def speak(self):
                return "Woof"
        
        animals = [Cat(), Dog()]
        for animal in animals:
            print(animal.speak())  # Вывод: Meow, Woof

<h1>что такое декоратор?</h1>

Декоратор в Python — это функция, которая принимает другую функцию (или метод, или класс) в качестве аргумента и возвращает модифицированную или новую функцию. 
Декораторы позволяют оборачивать дополнительную функциональность вокруг существующего кода без изменения его исходника.
<hr>
<h1>что такое асинхронность?</h1>
Асинхронность — это подход к выполнению задач, позволяющий обрабатывать несколько операций одновременно без блокировки основной программы.
Она основана на том, что задачи могут быть приостановлены и возобновлены позже, когда результат будет доступен, вместо того чтобы ожидать завершения каждой операции по порядку.
<hr>
Многопоточность — это возможность программы выполнять несколько потоков (threads) одновременно. Потоки — это легковесные единицы выполнения внутри одного процесса, которые могут работать параллельно.
<hr>


В Python, особенно в асинхронной программной модели (`asyncio`), ключевые понятия, такие как **корутина**, **фьючерс** и **таск**, играют важную роль. Вот что они означают и как они связаны друг с другом:

---

### **1. Корутина (Coroutine)**

#### Определение:
Корутина — это функция, которая определена с помощью `async def`. Она может быть приостановлена (`await`) и возобновлена позже. Корутина является базовым строительным блоком для асинхронного программирования.

#### Особенности:
- Корутина выполняется только при вызове `await` или при преобразовании её в задачу (`asyncio.create_task`).
- Она похожа на генератор, но работает в асинхронном контексте.

#### Пример:
```python
async def my_coroutine():
    print("Начало корутины")
    await asyncio.sleep(1)  # Асинхронная пауза
    print("Конец корутины")
```

---

### **2. Фьючерс (Future)**

#### Определение:
`asyncio.Future` — это объект, который представляет результат асинхронной операции, которая может завершиться в будущем. Он может быть в одном из состояний: **ожидание выполнения**, **выполнено успешно** или **выполнено с ошибкой**.

#### Особенности:
- Используется для управления состоянием и результатом асинхронных операций.
- Фьючерс — это низкоуровневый механизм, который редко используется напрямую.

#### Пример:
```python
import asyncio

async def set_future_value(future):
    await asyncio.sleep(1)
    future.set_result("Результат готов")

async def main():
    future = asyncio.Future()
    asyncio.create_task(set_future_value(future))
    print(await future)  # Ожидает завершения future

asyncio.run(main())
```

---

### **3. Таск (Task)**

#### Определение:
`asyncio.Task` — это обертка вокруг корутины, которая позволяет планировать её выполнение в цикле событий. Задача автоматически запускает выполнение корутины.

#### Особенности:
- Создаётся с помощью `asyncio.create_task` или `loop.create_task`.
- Может быть запущена в фоне.
- Возвращает объект, который можно использовать для отслеживания статуса задачи.

#### Пример:
```python
import asyncio

async def my_task(name):
    await asyncio.sleep(1)
    print(f"Задача {name} завершена")

async def main():
    task1 = asyncio.create_task(my_task("A"))
    task2 = asyncio.create_task(my_task("B"))
    await task1
    await task2

asyncio.run(main())
```

---

### **Связь между ними**

1. **Корутина** — это функция, которую можно выполнить, но сама по себе она ничего не делает, пока её не запланируют на выполнение.
2. **Таск** — это объект, который запускает выполнение корутины в цикле событий.
3. **Фьючерс** — это базовый объект, используемый для получения результата работы тасков и других асинхронных операций.

---

### **Сравнение**

| **Характеристика**        | **Корутина**           | **Фьючерс**                  | **Таск**                     |
|---------------------------|------------------------|------------------------------|------------------------------|
| **Что это?**              | Асинхронная функция    | Контейнер для результата     | Обертка для выполнения       |
| **Запуск выполнения**     | `await`               | Ручное управление            | Автоматический через `create_task` |
| **Цель**                  | Описание логики        | Управление результатом       | Планирование выполнения      |
| **Пример**                | `async def func()`    | `future.set_result()`        | `asyncio.create_task(func())`|

---

### **Когда что использовать**
- Используйте **корутины** для описания логики асинхронного поведения.
- Используйте **таски** для параллельного выполнения корутин.
- Используйте **фьючерсы**, если требуется низкоуровневое управление состоянием результата (например, при интеграции с внешними библиотеками).

<h1>RESTful API</h1>
REST (Representational State Transfer) — это архитектурный стиль для разработки веб-сервисов, позволяющий клиентам и серверам взаимодействовать с данными через API с использованием HTTP-запросов. RESTful API — это API, соответствующий принципам REST, где "RESTful" означает "следующий стандартам и принципам REST".
<br><br>
RESTful API основываются на **шести основных принципах** (или ограничениях), которые описал Рой Филдинг в своей диссертации. Эти принципы обеспечивают масштабируемость, простоту и производительность API. Рассмотрим их подробно:

---

### **1. Архитектурный стиль клиент-сервер (Client-Server)**
- **Суть**: Клиент и сервер должны быть разделены, чтобы каждая сторона могла развиваться независимо.
- **Преимущества**:
  - Клиент не знает внутреннего устройства сервера, он работает только с ресурсами через API.
  - Сервер не знает деталей пользовательского интерфейса клиента.
- **Пример**: Сервер предоставляет данные, а клиент (например, веб-приложение) отвечает за их отображение.

---

### **2. Отсутствие состояния (Stateless)**
- **Суть**: Каждый запрос от клиента к серверу должен быть самодостаточным и содержать всю необходимую информацию.
- **Преимущества**:
  - Серверу не нужно хранить данные о состоянии клиента между запросами.
  - Упрощение масштабирования: любой запрос можно обработать на любом сервере.
- **Пример**: Запрос к API содержит токен авторизации, поэтому сервер не сохраняет информацию о пользователе между запросами.

---

### **3. Кеширование (Cacheable)**
- **Суть**: Ответы от сервера должны быть помечены как кешируемые или некешируемые.
- **Преимущества**:
  - Снижение нагрузки на сервер.
  - Ускорение ответа для клиента.
- **Пример**: Ресурсы, такие как изображения или статичные данные, могут быть кешированы с помощью HTTP-заголовков (`Cache-Control`, `ETag`).

---

### **4. Единообразие интерфейса (Uniform Interface)**
- **Суть**: Интерфейс API должен быть стандартизирован и следовать установленным правилам.
- **Четыре свойства**:
  1. **Идентификация ресурсов**: Каждый ресурс должен иметь уникальный URL (например, `/users/123`).
  2. **Манипуляции с ресурсами через представления**: Клиент работает с ресурсами, отправляя данные (например, JSON) в запросах.
  3. **Самоописывающие сообщения**: Запросы содержат всю необходимую информацию (метод, заголовки, тело).
  4. **Гипермедийное управление (HATEOAS)**: Ответы могут содержать ссылки на связанные ресурсы.
- **Пример**: Запрос `GET /products/` возвращает список продуктов, где каждый элемент содержит ссылки на подробности о конкретном продукте.

---

### **5. Многослойная система (Layered System)**
- **Суть**: API может состоять из нескольких слоев (серверы приложений, кеши, балансировщики нагрузки), но клиент взаимодействует только с конечной точкой.
- **Преимущества**:
  - Масштабируемость.
  - Возможность внедрения посредников (например, прокси или балансировщиков) без изменения клиента.
- **Пример**: Клиент отправляет запрос на API, а прокси-сервер перенаправляет его на нужный сервер.

---

### **6. Код по требованию (Code on Demand) [необязательный принцип]**
- **Суть**: Сервер может отправить клиенту исполняемый код, который клиент выполняет.
- **Преимущества**:
  - Расширение функциональности клиента без обновления самого клиента.
- **Пример**: API может возвращать JavaScript-код, который выполняется на стороне клиента.
- **Важно**: Этот принцип редко используется, так как может быть сложным для реализации и снижать безопасность.

---

<hr>
Ответы серверов в протоколе HTTP обозначаются числовыми кодами состояния (status codes), которые классифицируются по группам. Каждый код сообщает клиенту о результате его запроса.

---

### 1xx: **Информационные ответы**  
Используются для предоставления дополнительной информации о состоянии запроса.

- **100 Continue**: Клиент может продолжить отправку запроса.  
- **101 Switching Protocols**: Сервер согласен переключить протоколы по запросу клиента.  
- **102 Processing (WebDAV)**: Сервер обрабатывает запрос, но ответа пока нет.  
- **103 Early Hints**: Предварительная информация перед окончательным ответом.

---

### 2xx: **Успешные ответы**  
Означают, что запрос клиента был успешно обработан.

- **200 OK**: Запрос успешно выполнен, данные переданы.  
- **201 Created**: Ресурс успешно создан.  
- **202 Accepted**: Запрос принят, но еще не обработан.  
- **203 Non-Authoritative Information**: Информация передана, но изменена сторонним сервером.  
- **204 No Content**: Успешный запрос, но контент отсутствует.  
- **205 Reset Content**: Клиенту нужно сбросить состояние представления.  
- **206 Partial Content**: Успешно передана только часть данных (используется при диапазонных запросах).  
- **207 Multi-Status (WebDAV)**: Передается несколько статусов для разных частей ресурса.  
- **208 Already Reported (WebDAV)**: Элемент уже был представлен в предыдущем ответе.  
- **226 IM Used**: Сервер обработал запрос с использованием технологии `Delta encoding`.

---

### 3xx: **Перенаправления**  
Сообщают клиенту, что необходимо выполнить дополнительное действие для завершения запроса.

- **300 Multiple Choices**: Есть несколько вариантов ответа.  
- **301 Moved Permanently**: Ресурс перемещен на другой URL навсегда.  
- **302 Found**: Ресурс временно находится по другому URL.  
- **303 See Other**: Рекомендуется другой URL для запроса.  
- **304 Not Modified**: Ресурс не изменен (используется для кеширования).  
- **305 Use Proxy**: Ресурс доступен только через прокси (устарело).  
- **307 Temporary Redirect**: Временное перенаправление с использованием того же метода.  
- **308 Permanent Redirect**: Постоянное перенаправление с использованием того же метода.

---

### 4xx: **Ошибки клиента**  
Сообщают, что проблема в запросе клиента.

- **400 Bad Request**: Некорректный запрос из-за синтаксической ошибки.  
- **401 Unauthorized**: Требуется аутентификация.  
- **402 Payment Required**: Зарезервирован для использования в будущем.  
- **403 Forbidden**: Доступ к ресурсу запрещен.  
- **404 Not Found**: Ресурс не найден.  
- **405 Method Not Allowed**: Метод запроса не поддерживается для этого ресурса.  
- **406 Not Acceptable**: Запрашиваемый формат данных не может быть предоставлен.  
- **407 Proxy Authentication Required**: Требуется аутентификация через прокси.  
- **408 Request Timeout**: Сервер не дождался завершения запроса.  
- **409 Conflict**: Конфликт при обработке запроса (например, попытка создать уже существующий ресурс).  
- **410 Gone**: Ресурс больше недоступен и не будет доступен в будущем.  
- **411 Length Required**: Отсутствует необходимая длина запроса.  
- **412 Precondition Failed**: Условие запроса не выполнено.  
- **413 Payload Too Large**: Размер тела запроса слишком велик.  
- **414 URI Too Long**: URI запроса слишком длинный.  
- **415 Unsupported Media Type**: Неподдерживаемый формат данных.  
- **416 Range Not Satisfiable**: Указанный диапазон данных недопустим.  
- **417 Expectation Failed**: Ожидание, указанное в заголовке `Expect`, не может быть выполнено.  
- **418 I'm a teapot**: Шутливый код (RFC 2324).  
- **421 Misdirected Request**: Сервер не может обработать запрос на данный ресурс.  
- **422 Unprocessable Entity (WebDAV)**: Сервер не может обработать запрос из-за семантической ошибки.  
- **423 Locked (WebDAV)**: Ресурс заблокирован.  
- **424 Failed Dependency (WebDAV)**: Предыдущий запрос завершился неудачей, и текущий зависит от него.  
- **425 Too Early**: Сервер не готов обработать запрос.  
- **426 Upgrade Required**: Клиент должен переключиться на другой протокол.  
- **428 Precondition Required**: Сервер требует выполнения предварительных условий.  
- **429 Too Many Requests**: Слишком много запросов за короткое время.  
- **431 Request Header Fields Too Large**: Заголовки запроса слишком большие.  
- **451 Unavailable For Legal Reasons**: Ресурс недоступен из-за юридических причин.

---

### 5xx: **Ошибки сервера**  
Сообщают, что сервер не смог обработать запрос.

- **500 Internal Server Error**: Внутренняя ошибка сервера.  
- **501 Not Implemented**: Сервер не поддерживает метод запроса.  
- **502 Bad Gateway**: Сервер получил недействительный ответ от вышестоящего сервера.  
- **503 Service Unavailable**: Сервер временно недоступен.  
- **504 Gateway Timeout**: Сервер не дождался ответа от вышестоящего сервера.  
- **505 HTTP Version Not Supported**: Используемая версия HTTP не поддерживается.  
- **506 Variant Also Negotiates**: Ошибка конфигурации сервера.  
- **507 Insufficient Storage (WebDAV)**: Сервер не может сохранить данные запроса.  
- **508 Loop Detected (WebDAV)**: Обнаружен бесконечный цикл.  
- **510 Not Extended**: Требуются дополнительные параметры для обработки запроса.  
- **511 Network Authentication Required**: Требуется аутентификация в сети.

---

<br>

__next__() — возвращает следующий элемент последовательности. Если элементы закончились, возбуждает исключение StopIteration.

Генераторы
Генераторы — это упрощённая версия итераторов. Они создаются с помощью функций, которые используют ключевое слово yield. Генератор автоматически создаёт итератор и управляет состоянием функции. Генератор не сохраняет данные, а просто их возвращает.

<h1>Шаблоны разработки:</h1>
Поведенческие, Структурные, Порождающие.

Поведенческие (Behavioral Patterns)
Эти шаблоны отвечают за взаимодействие между объектами и их поведение. например обсервер.

Структурные (Structural Patterns)
Эти шаблоны описывают способы упрощения структуры программы, объединения объектов и классов. например прокси и декораторы.

Порождающие (Creational Patterns)
Эти шаблоны отвечают за создание объектов, обеспечивая гибкость и контроль над процессом. например синглтон и фабрики.

super() — это встроенная функция Python, которая используется для вызова методов родительского (или базового) класса. Она полезна в случаях, когда вы хотите расширить или изменить поведение методов родительского класса в подклассах.

Индексы в СУБД (Системах Управления Базами Данных) — это структуры данных, которые используются для ускорения операций поиска и сортировки в таблицах. Они работают как указатели, позволяя СУБД быстрее находить строки без необходимости сканировать всю таблицу.

Ключи в базах данных — это специальные атрибуты (или комбинации атрибутов) таблицы, которые используются для идентификации записей и управления связями между таблицами. Разберём основные типы ключей и их предназначение.

HTTP (HyperText Transfer Protocol) — это протокол прикладного уровня, который используется для передачи данных между клиентом (например, браузером) и сервером через сеть. Он лежит в основе работы Всемирной паутины (World Wide Web) и используется для передачи гипертекста (например, HTML), изображений, видео и других данных.

Сокеты — это программные интерфейсы для установления двустороннего соединения между приложениями, работающими по сети или внутри одной системы. С их помощью приложения могут обмениваться данными через сеть, используя протоколы, такие как TCP, UDP и другие.

Как работают сокеты?
Создание сокета
Одна программа создаёт сокет и указывает тип соединения (TCP или UDP) и порт для взаимодействия.

Установка соединения
Сокет одной стороны "привязывается" к порту, а другой стороне передаются параметры соединения (IP и порт).

Обмен данными
После установления соединения приложения могут отправлять и получать данные.

Закрытие соединения
Когда обмен завершается, сокет закрывается, освобождая ресурсы.

Типы сокетов
TCP-сокеты (потоковые сокеты)

Используют протокол TCP (Transmission Control Protocol).
Обеспечивают надёжную передачу данных с контролем доставки и повторной отправкой при ошибках.
Подходят для приложений, где важна целостность данных (например, веб-серверы, чаты).
UDP-сокеты (датаграммные сокеты)

Используют протокол UDP (User Datagram Protocol).
Быстрее TCP, но не гарантируют доставку и порядок передачи данных.
Подходят для приложений реального времени, где важна скорость (например, видеозвонки, игры).
<hr>

HTTP-запрос — это сообщение, отправляемое клиентом (например, браузером или другим приложением) на сервер для выполнения определённого действия, такого как получение данных, отправка данных, удаление ресурса и т.д.

HTTP-запрос состоит из следующих компонентов:
1. Стартовая строка (Request Line)
Она содержит:

Метод — указывает действие, которое клиент хочет выполнить (например, GET, POST, PUT, DELETE и т.д.).
Пример: GET /index.html HTTP/1.1

Путь к ресурсу — указывает, к какому ресурсу обращается запрос.
Пример: /index.html

Версия протокола — указывает используемую версию HTTP.
Пример: HTTP/1.1

2. Заголовки (Headers)
Заголовки содержат метаинформацию о запросе. Они передаются в формате ключ: значение.

Примеры:
Host: example.com — указывает доменное имя сервера.
User-Agent: Mozilla/5.0 — информация о клиенте (браузере, приложении).
Accept: text/html — формат данных, который клиент хочет получить.
Content-Type: application/json — формат данных, отправляемых клиентом.
Authorization: Bearer <token> — используется для передачи токенов аутентификации.
Заголовки передаются строками и заканчиваются пустой строкой.

3. Тело запроса (Body)
Тело запроса присутствует только у методов, таких как POST, PUT, PATCH, которые отправляют данные на сервер.
Обычно используется для передачи:

Данных формы.
JSON-объектов.

Идемпотентность — это свойство операции, при котором повторное выполнение этой операции с одним и тем же входом не изменяет состояние системы или результат. Другими словами, выполнение одной и той же операции несколько раз подряд эквивалентно выполнению её один раз.

Python — это язык программирования, который поддерживает несколько парадигм. Вот основные из них:

---

### 1. **Императивное программирование**
Императивное программирование фокусируется на изменении состояния программы через команды (инструкции), которые выполняются последовательно.

**Особенности**:
- Программа описывает шаги, которые компьютер должен выполнить.
- Примеры: использование циклов, условных операторов и переменных для управления состоянием.

**Пример:**
```python
result = 0
for i in range(10):
    result += i
print(result)
```

---

### 2. **Объектно-ориентированное программирование (ООП)**
ООП организует код вокруг объектов, которые являются экземплярами классов. Каждый объект имеет состояние (атрибуты) и поведение (методы).

**Особенности**:
- Инкапсуляция, наследование, полиморфизм.
- Удобно для моделирования реальных систем.

**Пример:**
```python
class Animal:
    def __init__(self, name):
        self.name = name
    
    def speak(self):
        pass

class Dog(Animal):
    def speak(self):
        return f"{self.name} says Woof!"

dog = Dog("Buddy")
print(dog.speak())
```

---

### 3. **Функциональное программирование**
Функциональное программирование фокусируется на вычислении значений через функции, избегая изменения состояния и использования переменных.

**Особенности**:
- Функции высшего порядка.
- Чистые функции (без побочных эффектов).
- Рекурсия вместо циклов.

**Пример:**
```python
from functools import reduce

numbers = [1, 2, 3, 4, 5]
result = reduce(lambda x, y: x + y, numbers)
print(result)
```

---

### 4. **Процедурное программирование**
Процедурное программирование — это подмножество императивного программирования. Оно фокусируется на разделении программы на процедуры или функции.

**Особенности**:
- Код делится на небольшие модули (функции).
- Легко отлаживать и тестировать.

**Пример:**
```python
def add(a, b):
    return a + b

result = add(5, 10)
print(result)
```

---

### 5. **Метапрограммирование**
Метапрограммирование позволяет изменять структуру и поведение программы во время её выполнения. Python позволяет создавать метаклассы или динамически изменять классы.

**Особенности**:
- Использование метаклассов.
- Изменение структуры программы "на лету".

**Пример:**
```python
class Meta(type):
    def __new__(cls, name, bases, dct):
        dct['greet'] = lambda self: "Hello from meta!"
        return super().__new__(cls, name, bases, dct)

class MyClass(metaclass=Meta):
    pass

obj = MyClass()
print(obj.greet())
```

---

### 6. **Событийно-ориентированное программирование**
Эта парадигма фокусируется на обработке событий. Часто используется в графических интерфейсах или обработке сигналов.

**Пример:**
```python
import tkinter as tk

def on_click():
    print("Button clicked!")

root = tk.Tk()
button = tk.Button(root, text="Click Me", command=on_click)
button.pack()
root.mainloop()
```

---

### 7. **Асинхронное программирование**
Асинхронная парадигма позволяет писать программы, которые работают с несколькими задачами параллельно, не блокируя основное выполнение.

**Особенности**:
- Использует `asyncio` и асинхронные вызовы.
- Подходит для сетевого программирования и задач ввода-вывода.

**Пример:**
```python
import asyncio

async def say_hello():
    print("Hello")
    await asyncio.sleep(1)
    print("World")

asyncio.run(say_hello())
```

---

### Итог
Python — мультипарадигменный язык, что делает его универсальным. Это позволяет выбирать подходящую парадигму для каждой задачи, обеспечивая гибкость и эффективность при разработке.

<h1>Что такое MIDDLEWARE в Django?</h1>
Middleware — это фрагменты кода, которые выполняются на каждом запросе и ответе в Django-приложении. Они расположены между клиентским запросом (HTTP) и представлением (view), а также между представлением и окончательным ответом клиенту. Middleware помогает обрабатывать, изменять или анализировать запросы и ответы на разных этапах их жизненного цикла.
<br><br>
Пример работы Middleware:<br>
Клиент отправляет HTTP-запрос.<br>
Запрос проходит через цепочку middleware перед тем, как попасть в представление.<br>
Представление возвращает HTTP-ответ.<br>
Ответ снова проходит через цепочку middleware перед отправкой клиенту.<br>
Возможности Middleware:<br>
Обработка запроса и ответа.<br>
Добавление или удаление данных.<br>
Изменение заголовков.<br>
Проверка авторизации.<br>
Защита от атак, таких как CSRF.<br>
Логирование.<br>
Сжатие данных.<br><br>
Пример Middleware:<br>
SecurityMiddleware: добавляет заголовки безопасности, такие как X-Content-Type-Options.<br>
SessionMiddleware: позволяет использовать сессии.<br>
AuthenticationMiddleware: связывает пользователя с запросом, чтобы вы могли получить request.user.<br>
CsrfViewMiddleware: защищает от CSRF-атак.<br>
GZipMiddleware: сжимает HTTP-ответ для уменьшения объема данных.
